# Security reports

Report suspected vulnerabilities through the repository's **Security → Report a vulnerability** option when available. Include affected source revision, installation conditions, a minimal reproduction, expected/actual behavior and the likely impact. Use synthetic data and redact credentials, cookies, tokens, host details and personal collections.

Do not post secrets, working authentication bypasses against a real installation, private photos or database dumps in a public issue. If private reporting is unavailable, open an issue requesting a private contact method without the vulnerability details.

PakTrak is under active development. Fixes are developed against the current main branch; there is no promised response time or long-term support schedule. See [implementation status](docs/STATUS.md) for remaining qualification and operational work.

Operators should use HTTPS for phone access, protect generated credentials and backups, keep private database/broker/storage services off public ports, and retain a verified backup before upgrading. Follow the [operations guide](docs/OPERATIONS.md) for account controls, diagnostic references, hostname changes and recovery limitations.
